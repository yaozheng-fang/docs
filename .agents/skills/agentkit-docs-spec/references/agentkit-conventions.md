# AgentKit 适配

本文件说明通用质量标准在 AgentKit 中的适用方式。[根 `SPEC.md`](../../../../SPEC.md) 优先，产品规范作补充；协作约定见 [`AGENTS.md`](../../../../AGENTS.md)。标识 K 用于来源覆盖清单

## K1 读取实际规范

AgentKit 文档通常包括 VeADK、AgentKit CLI 和 API Reference，页面为 MDX，导航集中在 `docs.json`。产品规范通常位于：

- [VeADK 文档规范](../../../../productions/veadk/veadk_SPEC.md)
- [AgentKit CLI 文档规范](../../../../productions/agentkit-cli/agentkit-cli_SPEC.md)
- [API Reference 文档规范](../../../../productions/api-reference/api-reference_SPEC.md)

技能不重复定义个人账号、工作树、分支、提交和部署方式。这些行为沿用当前会话与适用的 `AGENTS.md`，不从 Google 仓库的流程推导授权

## K2 语言、标题与展示

| 事项 | AgentKit 的处理方式 |
| --- | --- |
| 中文语气 | 正式、直接、自然的书面语，避免口语和空泛修饰 |
| 普通名词 agent | 写作“智能体”，公开类名、配置键和产品名保留原文 |
| 中文术语解释 | 在正文自然说明作用，不加冗余括号译名 |
| 英文表达 | 自然表达同一事实，采用清楚一致的技术英语 |
| 页面标题 | 描述性短语，不使用步骤编号；后端标题遵循本仓库命名要求 |
| 命令/API 参考 | 允许用命令、路径或公开接口名作标题，便于查询 |
| 页面主标题 | 使用 frontmatter 的 title，不在正文重复 H1 |
| 长行 | 保证可读性与可复制性，不机械按英文字符数截断中文、URL、表格和字符串 |
| 产品与模型名称 | 使用目标产品真实名称和目标环境可用标识，不替换为 Google 专属名称 |

普通文档页面的 frontmatter 提供 `title`，不添加 `description`、副标题或外部目录字段：

```yaml
---
title: "配置模型"
---
```

HTTP API 单接口页另提供 `openapi`，绑定对应语言的规范文件、方法和路径。保留并维护站点语言切换使用的 `en_link` / `zh_link`，不能为简化 frontmatter 删除已有语言关联

## K3 Mintlify 组件

| 内容 | 优先采用 |
| --- | --- |
| 背景、兼容性和仓库明确要求的前置说明 | `<Note>` |
| 可选推荐做法 | `<Tip>` |
| 实际存在的删除、发布、费用、隐私或安全影响 | `<Warning>`，放在动作之前 |
| 连续操作 | `<Steps>` / `<Step>` |
| 互斥平台、语言或配置方式 | `<Tabs>` / `<Tab>` |
| 参数、后端和能力比较 | 普通 Markdown 表格 |
| 入口页的少量重点去向 | `<CardGroup>` / `<Card>` |

Google 通用指南把 Note 定位为非必需补充；AgentKit 产品规范可能明确要求用 `<Note>` 写前提。遵循实际产品规范，并确保前提在操作前醒目出现，不能被误解为可选。正常步骤、结果和普通链接不必装进提示框

组件服务于理解，不以大量卡片、标签页和提示框制造层级。避免为视觉效果更改语义标题或把关键内容藏在折叠区

## K4 三类产品的完整性要求

### VeADK

- 组件说明先交代用途和场景，再给最小示例、公开参数、默认行为与限制
- 每个会话、记忆和知识库后端独立提供连接、凭证、参数与示例，不能依赖另一个后端页补齐必需信息
- 参数表通常包含名称、类型、默认值和说明；环境变量说明默认值与作用；extras 列出包含的具体能力
- 工具页交代注册方式及必要的输入输出、上下文、长时任务和多模态行为
- 前端与部署指南交代启动、访问、验证以及实际云资源和授权影响
- 火山引擎与 BytePlus 的支持、区域、凭证和差异按证据说明，不把一侧配置当另一侧默认值

### AgentKit CLI

- 快速开始的鉴权能力必须满足后续部署步骤，不能把仅可调用运行时的身份写成管理资源的等价路径
- 命令参考覆盖全部公开子命令、别名、参数、选项、默认值和交互行为；参数表使用产品约定列名
- 配置参考先给整体结构，再解释字段和生效条件；写清文件由用户创建、工具生成还是需要编辑
- 工作流交代执行目录、文件生成、验证与限制，删除、覆盖、跳过确认和发布影响前置

### API Reference

- 覆盖方法、路径、用途、鉴权约定、参数、请求、响应和必要失败条件
- 关键嵌套类型给结构说明或准确引用，不只罗列模型名称
- 简单接口可用路由表，复杂请求给最小 curl 示例；流式接口解释媒体类型和事件边界
- 共享约定集中说明并链接，保持参考页精确而易查，不塞入过长教程

## K5 版本、双语与导航

- `productions/<product>/preview/{zh,en}` 通常是当前可编辑内容；`archives` 仅用于对应版本事实修正
- 明确目标版本，未发布能力只进入标明范围的 Preview；稳定归档不得混入后续能力
- 文档修改按适用规范核对命令/参数、配置、正文、示例、限制、双语、Changelog 和导航；粗看不自动扩大为完整版本更新
- 中英文按同一份事实和影响清单维护，不以目录一致代替内容等价
- Changelog 累计保留历史，按新到旧组织；条目链接页必须实际说明能力，不能用更新日志替代正文
- 新增或移动页面检查 `docs.json`，内部链接使用站点根路径且不带 `.mdx`；资源按真实目录定位
- 用户指定审查工作区时，保留该基线，不为满足更新流程而替换为另一份文档

## K6 对外内容边界

公开文档、提交和 PR 只说明用户价值、事实依据、变更范围和验证结果，不记录撰写工具、模型、执行环境或生成过程。产品自身公开的模型配置仍属于正常文档内容，应准确保留

不添加生成免责声明，不强制使用 Google 特定的 PR 标题或来源字段。不把内部函数、实现路径和管理流程写成用户说明；用户直接使用的公开 API、配置键、环境变量和自建文件路径应保留

署名、许可和贡献者要求以目标仓库的真实规则为准，不自动要求用户签署 Google 的贡献协议
