# 页面结构与模板

来源：Google ADK 的 integration-create、integration-review、adk-bot-review，Google 的 Headings and titles、Procedures，以及 AgentKit 本地页面约定。标识 P 用于来源覆盖清单

## P1 页面职责与现有范例

先确定读者最终要理解或完成什么，再决定页面类型。说明应足以让读者成功操作，篇幅和位置与主题重要性相称；已有文档或 API 参考已经覆盖时，优先链接，不再写一份重复介绍

新建集成文档时，先完整阅读同类别正式页面。深度集成审查按上游做法尽量阅读至少 5 篇相关页面；样本不足时使用真实可得页面并说明，不凑数、不把粗看扩展为大范围调研。根据类别、领域、支持语言和结构选择，而不只看文件名或元数据

现有页面是结构与用语范例，不是 API 事实的最终依据；若页面与当前根规范或发布接口冲突，采用已核实的规范和事实

| 页面类型 | 首要任务 | 应提供的信息 |
| --- | --- | --- |
| 教程/快速开始 | 获得首次成功 | 明确结果、前提、最短完整路径、可观察结果 |
| 操作指南 | 完成一个具体任务 | 场景、前提、步骤、验证、限制和必要失败处理 |
| 概念说明 | 建立理解 | 通俗定义、适用场景、关键关系、行为、最小例子 |
| 参数/CLI/API 参考 | 快速查询 | 用途、准确语法、字段和默认值、返回值、边界、必要示例 |
| 故障排查 | 找到并解决问题 | 现象、可能原因、检查方式、解决动作、结果 |
| 第三方集成 | 把外部能力接入产品 | 价值与用途、支持范围、服务准备、安装、接入、验证、配置、资源 |
| 入口页 | 选择正确路径 | 能力范围、简短比较、重点入口与下一层说明 |

## P2 教程与操作指南

推荐顺序如下，按实际内容增减，不增加空章节：

1. 说明将完成的任务和适用场景
2. 列出必要软件、版本、账号、权限、凭证、区域和外部资源
3. 按依赖顺序操作，说明工作目录、需要创建或修改的文件、命令与占位符
4. 说明输出、页面变化或查询结果，帮助读者判断成功
5. 补充重要限制、常见失败检查及必要清理

同一条首次使用路径不能前面把两种鉴权写成等价选择，后面又依赖其中一种专属权限。配置文件需要先生成时，应在编辑前说明生成步骤；示例不能假设读者已经拥有未介绍的资源

每一步只解决一个决定。不同平台或互斥方式使用分节或 Mintlify 标签页，先给推荐方式及选择依据；不要在主路径中反复插入替代方案

## P3 概念、组件与扩展点

- 先解释能力是什么、解决什么问题、什么时候使用，再引入类名和参数
- 使用自然语言描述行为和数据关系，不依靠类继承图、内部函数列表或源码路径建立概念
- 区分默认行为、可选配置、推荐做法和产品限制，说明它们成立的条件
- 提到“可以自定义”“支持扩展”时给实际注册或使用方法及必要示例；不以名称清单代替说明
- 同类后端可统一模板，但每页的连接、凭证、参数和示例要独立完整
- 内存后端的数据生命周期、外部存储的连接条件、自动创建资源和用户隔离方式应明确

可用结构：用途与场景、最小示例、参数与配置、运行行为、限制。需要额外依赖时增加依赖说明；没有依赖时不为模板新增空节

## P4 MCP 工具集成

推荐结构：

- 使用场景：说明用户能完成什么，避免宣传语
- 前提条件：可用服务器、地址、协议、账号、API Key 或授权方式，附真实获取入口
- 安装：需要安装客户端或服务器时写清包名、版本要求与启动方式
- 接入智能体：最小完整示例，按实际支持的编程语言分开
- 可用工具：工具名称与用途表，必要时说明输入输出和约束
- 可选配置：额外请求头、环境变量、超时、认证和传输差异
- 相关资源：官方文档、源代码、包仓库或支持渠道

服务器同时支持本地 stdio 和远端 HTTP 时，说明两种连接方式及其前提；只支持一种就只写一种。多语言示例和传输方式可以使用嵌套标签页，但层级与缩进必须正确，不能暗示未经验证的语言支持

## P5 可观测性集成

推荐结构：一段用途说明、能力概览、安装、凭证与初始化、观察一次真实调用、相关资源

示例应覆盖一次可被追踪的完整智能体调用，并说明在哪里看到结果。说明数据发送到哪里、工作空间或项目如何选择，以及确实存在的敏感信息或费用影响

安装、初始化、调用很短且没有独立解释时，可合并成一个能复制的端到端示例，避免拆成许多只有代码的小节。介绍平台能力时只写与本次集成相关且有依据的内容

## P6 插件与其他连接器

推荐结构：使用场景、前提条件、安装、注册与调用示例、可用工具/方法、可选配置、相关资源

- 写清实际接入的扩展点，例如插件、回调、工具集或标准协议，不把普通的任意 HTTP 调用包装成深度产品集成
- 说明包名、安装要求、账号凭证和注册方式；一份可复制示例应能展示能力被使用
- 平台专属的深入用法可链接到厂商文档；与已有集成页重合的内容优先扩展或链接现有页
- 页面标题体现产品、能力类别和作用对象；实际标题、文件名与导航遵循 AgentKit 仓库规则
- 简介用简短、具体的动作表达用途，避免重复标题、罗列一串技术名或作过度承诺；本技能不引入 Google 的目录元数据字段

## P7 CLI、配置与 API 参考

### CLI

逐个列出目标版本的公开命令与选项，不只挑常用部分。每个命令条目说明用途、参数/标志、默认值、必填性、别名、交互行为和最小示例；删除、覆盖、确认和发布的影响明确标注

命令参考允许用命令名作标题，操作指南则用任务型标题。说明自动检测和自动推断的来源，不能只写“自动”。参数表和例子采用同一组名称与行为

### 配置

提供能理解整体结构的示例，再解释各配置块。说明字段类型、默认值、必要性、取值范围、来源优先级和实际生效条件；可选块应说明启用后引入什么资源或行为

涉及用户文件时，说明文件名、目录以及创建或生成方式。凭证使用环境变量或明确占位符；部分配置片段不能冒充完整可运行配置

### HTTP API

说明方法、路径、用途、鉴权约定、路径/查询参数、请求体、响应和必要失败条件。接口组可合并路由表，但复杂对象不能只列一个类型名

- 关键嵌套字段有结构说明或直接链接到相应定义
- 对复杂请求给最小可用请求和响应示例，能理解如何组装请求
- 说明枚举、默认值、必填性、分页、时间单位和内容类型等实际适用约束
- 流式接口说明事件格式和边界，异步接口说明如何查询状态；不把这些行为写成普通同步 JSON 请求
- 简单 GET 路由不必每个复制一个示例；共享约定集中说明并在需要处链接

## P8 收尾与内容边界

不默认增加“下一步”或重复总结。确有下一项任务时给具体链接；相关资源章节只保留能帮助读者的链接

草稿有缺少的图片、凭证来源、未验证示例等事项时，在交付说明中明确列出；不要把编辑备注、内部任务或生成过程放进公开页面，也不要把草稿标成已完成验证的正式内容
