# AgentKit 文档写作规范

帮助读者理解能力、完成任务并查到准确的接口信息。本技能整理 Google ADK 文档 Skill 与 Google Developer Documentation Style Guide 中的可复用规则，并说明 AgentKit 适配方式；出处、覆盖范围与未直接采用的规则见来源清单

## 先确定范围

1. 区分新写、修改、粗看、完整审查和文档 PR 审查。粗看只给经过上下文确认的代表问题；审查不自动授权修改文件、发布评论或创建、关闭 PR
2. 读取本仓库的 [协作约定](../../../AGENTS.md)、[根文档规范](../../../SPEC.md) 和对应产品规范：[VeADK](../../../productions/veadk/veadk_SPEC.md)、[AgentKit CLI](../../../productions/agentkit-cli/agentkit-cli_SPEC.md) 或 [API Reference](../../../productions/api-reference/api-reference_SPEC.md)
3. 确认读者、任务、产品和目标版本。以用户指定内容为基线；审查工作区时保留未提交改动，不擅自切换到远端版本
4. 区分教程、操作指南、概念说明、参考文档、故障排查和集成文档。按读者任务选择结构，不给所有页面套同一个模板

## 规则优先级

当前会话的明确用户要求优先，协作方式遵循适用的 `AGENTS.md`；文档要求以根 `SPEC.md` 为最高依据，产品规范和本技能作补充。修改规范或技能时，同步核对这些文件的规则和相互引用。Google 原规则中的产品名称、目录机制和运营流程不直接套用到 AgentKit；构建器专属规则不纳入本技能

中文采用正式、直接、自然的书面表达；英文采用清晰、友好、克制的技术文体。公开类、参数、配置键和用户文件名应准确保留；内部调用链和私有实现不作为正文主线

## 编写与修改

- 写之前完整阅读同类已发布页面，学习结构和约定；API、默认值和版本仍以可靠事实来源为准
- 首段交代用途和适用场景，接着给最短可用路径，再提供完整参数、限制和高级用法；参考页按查询需求组织
- 前提和条件位于动作之前，步骤按执行顺序排列，关键操作提供可判断成功的结果或验证方式
- 参数名称、类型、默认值、必填性、支持范围和失败条件有据可查；不用“等”“支持自定义”掩盖缺失信息
- 示例依赖、凭证、执行目录和上下文明确；可复制执行，或明确标为签名、配置片段、伪代码并给出必要上下文
- 修改限于本次沟通目标，保留无关内容，不顺手改写示例变量、重排代码或扩张为全站重构
- 按任务范围检查双语、导航、链接、示例和 Changelog；不能在润色中引入未经核实的新事实

## 核心质量标准

- 内容能帮助读者完成任务，不以营销描述、接口名称堆积或源码走读取代说明
- 标题和章节层级合理，没有空标题、重复内容和为了模板而增加的小节
- 术语一致，指代明确，主动说明谁执行动作；条件、默认行为、推荐做法和限制分开表达
- 内容、示例和链接与目标版本一致，没有虚构能力、依赖、路径或外部链接
- 破坏性操作、发布、费用、公网访问和敏感数据处理在操作前说明实际影响
- 结论与验证范围一致：没有运行示例就不声称可运行，没有核对来源就不声称接口正确

## 交付与验证

写作任务交付具体内容，并简述修改范围、验证结果和仍需确认的事实。审查任务先报告影响读者成功使用的问题，再报告结构、语言和排版问题；格式与审查深度一致

执行与任务相称且已获授权的检查。格式和结构检查不能替代示例验证；纯写作粗看不需要启动云资源、运行完整测试套件或逐条请求线上接口。外部评论、PR 操作和发布遵循已有授权，不因使用本技能增加这些动作
