VeADK 自 1.0.5 起使用 Python 标准库 `logging` 输出运行日志，不再依赖 Loguru。VeADK 自身的 logger 位于 `veadk` 命名空间，默认写入标准输出，便于被容器平台和日志采集器收集。

## 设置日志级别

通过 `LOGGING_LEVEL` 环境变量设置 VeADK 日志级别。该变量应在导入 VeADK 前设置，默认值为 `DEBUG`。

```bash lines
export LOGGING_LEVEL=INFO
python app.py
```

可使用 Python `logging` 支持的标准级别，包括 `DEBUG`、`INFO`、`WARNING`、`ERROR` 和 `CRITICAL`。

## 日志格式

每条日志包含时间、级别、调用位置和消息：

```text lines
2026-07-14 10:30:00 | INFO | app.py:20 - Request completed
```

当代码运行在正在记录的 OpenTelemetry span 中时，日志会自动增加 `trace_id`，便于在日志系统和链路追踪系统之间关联同一次请求：

```text lines
2026-07-14 10:30:00 | INFO | app.py:20 | trace_id=0123456789abcdef0123456789abcdef - Request completed
```

在交互式终端中，时间、级别和调用位置使用颜色区分；标准输出被重定向或采集时，不会写入 ANSI 颜色转义序列。

## 与应用日志集成

应用可以使用标准库 logger 输出自己的日志，并单独控制 `veadk` 命名空间的级别：

`LOGGING_LEVEL` 控制 VeADK 日志；应用自己的 logger 需要独立配置 handler，或在导入 VeADK 前调用 `logging.basicConfig()`。已有根 handler 时，`basicConfig()` 默认不重新配置。下面的示例运行后应显示 `Agent initialized`

```python lines
import logging

logging.basicConfig(level=logging.INFO, format="%(levelname)s | %(name)s | %(message)s")

from veadk import Agent
logging.getLogger("veadk").setLevel(logging.INFO)
app_logger = logging.getLogger("company_assistant")

agent = Agent(name="company_assistant")
app_logger.info("Agent initialized")
```

VeADK 的 handler 不向 Python 根 logger 传播，因此修改根 logger 不会重复输出 VeADK 日志。需要把 VeADK 日志发送到自定义后端时，可以按标准 `logging` 用法为 `logging.getLogger("veadk")` 添加 handler。

## 调度边界日志

VeADK 在 INFO 级别输出结构化调度边界日志，用于定位请求耗时和调用链路问题。每条日志以方括号前缀标记所属阶段，并携带会话 ID、模型名称、耗时等关键字段。日志中的耗时以毫秒为单位，取自单调时钟。

| 前缀 | 来源 | 记录内容 |
| :--- | :--- | :--- |
| `[turn-dispatch]` | `Runner` | 每轮调用的开始与结束、追踪数据保存的开始与结束，包含会话 ID、消息数量、输出长度和总耗时。 |
| `[tool-dispatch]` | 工具调度层 | 函数工具调用的进入与退出、工具名、线程池配置、并行调用计数；`run_code` 和 `bash_tool` 的进入、远程调用或子进程的开始与结束、超时与取消。 |
| `[llm-dispatch]` | 模型客户端 | 模型请求的准备、发送、首个增量到达和结束，包含模型名称、流式模式、输入条目数、工具数量、响应数和总耗时；首个输出到达时记录 TTFT。观测到协议响应 ID 时额外输出一条包含模型名称、线路协议和响应 ID 的日志。 |
| `[http-dispatch]` | 火山引擎签名请求 | HTTP 请求的发送开始与结束，包含 action、host、状态码、请求体大小和耗时。 |

<Note>
调度边界日志在 INFO 级别输出。将 `LOGGING_LEVEL` 设为 `INFO` 即可查看，无需开启 `DEBUG`。日志写入失败不会影响智能体执行。
</Note>

## 流式输出日志

`Runner` 在流式执行中不会逐个输出中间的 partial chunk。思考内容会在一个完整片段结束时记录一次，最终回答、工具调用和工具结果也按完整事件记录。事件仍会原样流式返回给调用方；该行为只减少日志中的逐 token 噪声。

<Warning>
  `DEBUG` 日志可能包含模型输出、思考内容、工具参数和工具结果。在生产环境处理敏感数据时，应将 `LOGGING_LEVEL` 设为 `INFO` 或更高，并按组织要求配置日志访问权限和保留周期。
</Warning>
