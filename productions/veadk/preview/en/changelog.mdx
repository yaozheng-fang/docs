This changelog cumulatively lists all public user-facing changes from VeADK 1.0.0 through the current version. Unreleased changes are listed in the "Unreleased" section; released versions are ordered newest first.

## Unreleased

| Module | Change details | Link |
| --- | --- | --- |
| Studio model selection | Model selection in custom creation, smart generation, and skill generation is now filtered by cloud provider: BytePlus mode shows only BytePlus-compatible models, while Volcengine mode shows all models. Switching cloud providers automatically migrates the model and API endpoint to the corresponding provider defaults. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio knowledge base | Custom agent creation adds the OpenViking knowledge base backend; service URL, API key, knowledge owner ID, resource URI, and resource index can be configured on the creation page and are written to the generated project's environment variables. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) · [Store knowledge in OpenViking](/productions/veadk/preview/en/components/knowledge/openviking) |
| Studio tracing | The cloud-Runtime trace query on the conversation page now selects the APMPlus OpenAPI endpoint by cloud provider: `open.volcengineapi.com` for Volcengine and `open.byteplusapi.com` for BytePlus, preventing failed trace queries under BytePlus mode caused by using the wrong endpoint. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Skills | When skills are loaded through Harness, CLI-generated agent code, or the AgentKit session capability service, VeADK automatically configures a local code executor for `SkillToolset`, so skill scripts run without additional configuration. | [Skills](/productions/veadk/preview/en/components/agent/skills) |
| Studio evaluation | Optimization snapshots from automatic evaluation are now persisted to Studio persistent storage: when `VEADK_STUDIO_TOS_BUCKET` and `VEADK_STUDIO_TOS_REGION` are configured (the deploy command auto-creates the bucket), snapshots are stored in TOS, survive process restarts, and are shared across instances. When persistent storage is not configured, snapshots remain in process memory and are lost on restart. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | When `veadk studio deploy` automatically provisions an Identity user pool, a TOS bucket, or sandbox Tools, the success output additionally prints a summary of configured cloud resources: each sandbox Tool type and ID, the private TOS storage address, user pool ID, client ID, and a link to the Identity console for the corresponding cloud provider. It also notes that password sign-in is disabled by default and that an SSO identity provider must be configured before inviting users. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | `--user-pool-id` and `--allowed-client-id` are now optional for `veadk studio deploy`. When omitted, the deploy command creates or reuses a named VeIdentity user pool (`veadk-studio-{vefaas-app-name}`) and web client (`veadk-studio-{vefaas-app-name}-web`) in the region selected by `--region`, and prints the Identity region, user pool ID, user pool domain, and client ID on completion. Passing both options still uses existing resources with the original cross-region lookup behavior. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | Deploying a new Runtime to AgentKit supports configuring the cloud build resources: TOS bucket, Container Registry (CR), and CodePipeline. Each resource group supports auto-create (default), specify names, or select existing; when selecting existing, Studio loads the available resource list for the current account via the server. The selected resources are recorded as Runtime tags and preserved when updating an existing Runtime. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio Skill Center | A "Skills" page is added to the sidebar for skill space management: browse skill spaces by region and name, with create, edit, and delete support. Administrators see all spaces; non-admins see only their own. Within each space, skills can be uploaded as ZIP archives (up to 20 MiB), browsed as a file tree, downloaded as ZIP, and deleted. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio skill generation | The Skill Center adds Dev Sandbox skill generation: creates independent development sandbox sessions via a DevEnv Tool to generate ADK-format skills from natural-language descriptions. Supports up to 3 parallel candidate groups with model and style selection, automatic format-validation repair (up to 2 attempts), iterative refinement, and direct publishing to a skill space; also supports optimizing existing skills with overwrite publishing. Available only to `developer` and `admin` roles and requires an administrator-configured DevEnv Tool. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio chat modes | The "Create Skill" mode is removed from the new-conversation mode selector; skill creation is now handled exclusively through the Skill Center using the Dev Sandbox. `veadk frontend`, `veadk studio`, `veadk studio deploy`, and `veadk studio update` remove the `--sandbox-skill-creator-tool-id` (`--skill-creator-tool-id`) option and the `SANDBOX_SKILL_CREATOR` environment variable. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio system information | The "System info" entry in the account menu changes from a dialog to a full page. In addition to the Studio version, it now shows sandbox information (configured Codex, OpenClaw, Hermes, and Dev Sandbox Tool IDs) and user pools (VeIdentity user pools associated with the current Studio, showing name, UID, domain, and region). The page is available only to users with agent-management access, and resource identifiers are read-only. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio login | When using BytePlus as the cloud provider with VeIdentity login, the default login-button label is now "BytePlus Identity"; the volcengine default remains "火山引擎 Identity". Setting `--oauth2-provider-label` (or `OAUTH2_PROVIDER_LABEL`) always takes precedence. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | While a deployment is in progress, the workspace detail page focuses on the deployment progress: it keeps the agent heading and a scrollable deployment panel visible and hides the other detail tabs and content; the normal detail tabs return after the deployment ends. Custom creation, code-package deployment, and updating a deployed agent all follow this behavior. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio automation | The "Configure Coding Agents" card is now enabled only when Studio is accessed at `http://127.0.0.1`; when accessed via any other hostname (including `localhost` or a deployed VeFaaS public URL), the card appears disabled with a "仅本地部署可用" tooltip. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | After a successful deployment, Studio retries probing the Runtime endpoint for up to 60 seconds before timing out, reducing the frequency of the "Deployed, not yet connected" state. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio deployment | When a deployment fails or is cancelled, the progress card now provides a "Return to edit" button that takes you back to the draft to adjust the configuration and start a new deployment. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio skill generation | The skill generation workbench improves its layout: a "Basic info" section is added, the Goal field is marked as required; the "Generation configuration" section is renamed to "Generation plan" (or "Optimization plan" when optimizing), and the model and style within each plan are marked as required. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio Skill Center | The skill creation entry in the Skill Center is relabeled from "Dev Sandbox create" to "Auto-create", and the empty-state hint is updated accordingly. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio sandbox | `--sandbox-dev-tool-id` and the `SANDBOX_DEV` environment variable are no longer restricted to Volcengine deployments; BytePlus deployments and updates now support the Dev Sandbox: deployments auto-create the DevEnv Tool, and updates detect and repair missing Tools. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio video creation | The new-conversation page adds a "Video creation" workspace mode that generates videos from a text prompt and optional reference assets. It supports text-to-video, reference-to-video, video editing, video extension, and first/last-frame task modes with configurable aspect ratio, resolution, and duration. Generation runs in two stages — prompt enhancement and video generation — and the result can be previewed and downloaded. Volcengine uses the `doubao-seedance-2-5-260628` generation model and `doubao-seed-2-1-pro-260628` enhancer model; BytePlus uses `dreamina-seedance-2-5-260628` and `dola-seed-2-1-turbo-260628`. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio skill customization | The new-conversation page adds a "Skill customization" workspace mode that provides a quick entry point for skill generation and optimization, reusing the Skill Center's Dev Sandbox skill generation. The mode is available only to `developer` and `admin` roles and appears only after an administrator configures a usable Dev Sandbox. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio persistent storage | Video creation and other capabilities add Studio persistent storage: `veadk studio deploy` automatically creates or reuses a private TOS bucket named `veadk-studio-<account ID>`; local startup is configured via the `VEADK_STUDIO_TOS_BUCKET` and `VEADK_STUDIO_TOS_REGION` environment variables. Reference asset upload and result storage depend on this storage. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
| Studio system info | System information page access is restricted from "agent-management access" to the `admin` role only, and a new "Storage" section shows the TOS address used by Studio persistent storage. | [Studio agent workbench](/productions/veadk/preview/en/components/frontend/studio) |
