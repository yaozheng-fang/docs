## 1.0.7

VeADK 1.0.7 was released on July 23, 2026. The following table lists its public user-facing changes. See the [GitHub Release](https://github.com/volcengine/veadk-python/releases/tag/1.0.7) for the complete commit history.

| Module | Change details | Link |
| --- | --- | --- |
| Code sandbox | `run_code` adds `bash` language support to run shell scripts in the AgentKit sandbox, with `exec_dir`, `env`, `hard_timeout`, and `max_output_length` parameters that control the working directory, environment variables, hard timeout, and maximum output length. | [Code sandbox](/productions/veadk/archives/1.0.7/en/components/tools/code-sandbox) |
| Studio creation modes | Adds Skill creation across two independent AgentKit CodeEnv sessions; candidates can be compared, downloaded as a ZIP, or published to AgentKit, and the mode is available to developers and admins only. Also adds temporary conversations that are deleted on exit and are not written to normal Studio history. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Studio smart search | Adds agent-aware smart search over conversation history, the mounted web-search tool, knowledge base, and long-term memory. Agent metadata advertises mounted sources, and Studio disables unavailable sources. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Studio roles and access | Adds `--admin` and `--developer` to `veadk studio`, `veadk frontend`, and `veadk studio deploy`. The UI displays the signed-in user's email, role badge, and OAuth profile picture. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Studio update command | Adds `veadk studio update --vefaas-app-name <name>`, which rebuilds Studio from a local VeADK checkout while preserving the existing URL, SSO, IAM role, gateway, environment variables, title, and logo. When `--region` and `--project` are omitted, it searches Beijing and Shanghai across all visible projects. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Studio deployment | `veadk studio deploy` automatically creates the two AgentKit CodeEnv Tools used by temporary chats and Skill creation; existing Tool IDs can be supplied with `--sandbox-chat-codex-tool-id` and `--sandbox-skill-creator-tool-id`. After deployment, client sign-in skips repeated OAuth consent. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Feishu channel | `FeishuChannelExtension` can fetch thread history and quoted messages through the Feishu OpenAPI, using `include_parent_message`, `include_thread_history`, and `thread_history_limit`, and prepends the quoted or thread content to the inbound message. | [Feishu channel](/productions/veadk/archives/1.0.7/en/components/extensions/feishu-channel) |
| Studio workbench | Refines the custom-creation workbench: local Skills accept folders or ZIP files with automatic format detection; AgentKit Skill Spaces and their Skills can be browsed by region and project; the deployment page shows the agent topology and supports configuration export and source download. It also improves runtime management and responsive layout, new-chat startup, the agent runtime selector, video rendering, and tool-call status display. | [Studio agent workbench](/productions/veadk/archives/1.0.7/en/components/frontend/studio) |
| Dependencies | Relaxes the `psycopg2-binary` version constraint to `>=2.9.10`; requires the AgentKit SDK to provide default CORS configuration. | [Installation](/productions/veadk/archives/1.0.7/en/get-started/installation) |

## 1.0.6

VeADK 1.0.6 was released on July 20, 2026. The following table lists its public user-facing changes. See the [GitHub Release](https://github.com/volcengine/veadk-python/releases/tag/1.0.6) for the complete commit history.

| Module | Change details | Link |
| --- | --- | --- |
| Studio branding | `veadk studio` and `veadk frontend` add `--site-title` (at most 6 characters) and `--site-logo` (local image or HTTP(S) URL, at most 5 MB; PNG, JPEG, GIF, WebP, AVIF, ICO supported) to set the system name and logo. The logo is used in the sidebar, login page, and browser favicon; the system name also becomes the browser page title. Omitting `--site-title` keeps the default `VeADK Studio`. The equivalent environment variables are `VEADK_SITE_TITLE` and `VEADK_SITE_LOGO`. Cloud deployment accepts the same options; remote images are downloaded during deployment and bundled into VeFaaS. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
| Studio deployment | `veadk studio deploy` supports `--region` to select the deployment region (`cn-beijing` by default, `cn-shanghai`); VeFaaS, API Gateway, and other resources are created in the selected region. A new `--project` selects the VeFaaS function project and defaults to `default`. Deployment automatically locates the VeIdentity user pool and client across Beijing and Shanghai, emitting a warning and continuing when matched cross-region. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
| Studio deployment IAM | `veadk studio deploy` checks `ServerlessApplicationRole` before deployment and creates the role with the `vefaas_full_access` custom policy and required system policies when it is missing. This check runs even when `--iam-role` is provided. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
| Studio authoring and debugging | System prompts now support a WYSIWYG Markdown editor with heading and list shortcuts. Initialization, session, and conversation failures show credential-redacted error details and Runner logs that can be expanded and copied. Agent names are validated against Google ADK rules: they must start with an ASCII letter or underscore, contain only ASCII letters, digits, and underscores, cannot use the reserved name `user`, and must be unique within the Agent tree. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
| AgentKit deployment | Feishu, knowledge-base, short-/long-term memory, and observability settings appear in their respective feature sections; their values are converted to runtime environment variables only during deployment. Selecting an observability exporter also enables the corresponding `ENABLE_*` flag. These values are not written to generated source or exported YAML; the deployment page mirrors them for review. Multi-instance deployments should use a database-backed short-term memory store; when `run_sse` returns 404, the UI suggests checking whether an in-memory or SQLite session landed on a different instance. When deploying from the bundled Web UI, cloud image build failures include a credential-safe build-log excerpt so dependency or Dockerfile errors can be diagnosed directly. | [Deploy to AgentKit](/productions/veadk/archives/1.0.6/en/deploy/agentkit) |
| Studio runtime management | Improved the runtime management view and responsive layout. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
| Feishu channel | Toggling the Feishu channel on the deployment page regenerates the project so that `app.py`, the `extensions` dependency, and runtime environment variables stay aligned before deployment. | [Studio agent workbench](/productions/veadk/archives/1.0.6/en/components/frontend/studio) |
