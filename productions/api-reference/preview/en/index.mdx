The HTTP API reference is organized by service: Agent API Server and Harness Runtime. Select the service you deployed to find its request parameters, responses, and examples

| Service | Use cases | Reference |
| --- | --- | --- |
| Agent API Server | Run loaded agents and manage applications, sessions, artifacts, and memory; the development service also exposes evaluation and debugging endpoints | [Agent API Server API](/productions/api-reference/preview/en/agent-api-server/overview) |
| Harness Runtime | Invoke Harness with request-level model, tool, and skill settings, manage sessions, and manage scheduled jobs when enabled | [Harness Runtime API](/productions/api-reference/preview/en/harness-runtime/overview) |

The services can expose the same path with different request fields, defaults, or authentication requirements. Follow the reference for the service you are calling. Each endpoint page displays path, query, header, and body parameters alongside response schemas and examples

## Call an endpoint

Local addresses in examples refer to development services. For a deployed service, use its actual address and required credentials. Endpoint pages provide cURL, Python, and JavaScript examples and an interactive request panel

Streaming endpoints return `text/event-stream`. Use the streaming examples on the endpoint page to read events as they arrive. The cURL `-N` option disables output buffering

<Note>
Create, update, delete, agent execution, and evaluation requests act on the selected service. Check the service address and resource identifiers before sending a request. Agent execution and cloud resources can incur charges
</Note>
