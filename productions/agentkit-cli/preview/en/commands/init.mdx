`init` creates a new agent project from a built-in template, or wraps an `Agent` from an existing Python file as a deployable AgentKit app. The generated project includes an entry file, dependency file, `agentkit.yaml`, and `.dockerignore`; use `agentkit config` to adjust it, then `agentkit launch` to build and deploy.

## init

Create a project from a built-in template. When `--template` is omitted, the command lists templates and asks for an ID, key, or name; use `--list-templates` to only print the list and exit.

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `[project_name]` | Project name. | `simple_agent` |
| `-t, --template <template>` | Template ID, key, or name. Available keys: `basic`, `basic_stream`, `a2a`, `eino_a2a`, `agent_server`, `langchain_basic_stream`, `basic_go`, `a2a_go`. | Interactive selection |
| `--directory <path>` | Output directory, resolved relative to the current directory; the project name is not appended | `.` |
| `--agent-name <name>` | Agent name. | `Agent` |
| `--description <text>` | Agent description. | Template default |
| `--system-prompt <text>` | Agent system prompt. | Template default |
| `--model-name <name>` | Model name in Ark. | Template default |
| `--model-api-base <url>` | Model API base URL. | — |
| `--model-api-key <key>` | Model API key; written into runtime environment config. | — |
| `--tools <list>` | Comma-separated tools to include. | — |
| `--list-templates` | List template IDs, keys, and names, then exit. | `false` |

`--model-api-key` writes the actual key to the generated `agentkit.yaml`. Create the project first, then follow the [Quickstart](/productions/agentkit-cli/preview/en/quickstart) to configure ignore files and model credentials so keys are not committed or packaged in the image

```bash lines
agentkit init my-agent --template basic --directory ./my-agent

agentkit init go-agent --template basic_go --directory ./apps/go-agent
```

Without `--directory`, files are written directly into the current directory. The examples above write to `./my-agent` and `./apps/go-agent`. Enter the corresponding directory before configuring or deploying

## init --from-agent

Wrap an existing Python file that defines a VeADK `Agent`. The CLI copies the source file, generates a wrapper entry point and `requirements.txt`, and creates lifecycle config.

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `[project_name]` | Project name; generated from the source file when omitted. | `agentkit-<file>` |
| `-t, --template <template>` | Select a template compatible with `--from-agent`: `basic`, `basic_stream`, or `agent_server`. When provided, it maps automatically to the corresponding wrapper type. | — |
| `-f, --from-agent <path>` | Python file containing the `Agent` definition. | Required |
| `--agent-var <name>` | `Agent` variable name in the file; auto-detected when omitted. | Auto-detected |
| `--wrapper-type <type>` | Wrapper type: `basic`, `stream`, or `agent_server`; when used with `--template`, it must match the selected template. | `basic` |
| `--directory <path>` | Output directory, resolved relative to the current directory; the project name is not appended | `.` |

```bash lines
agentkit init wrapped-agent --from-agent ./agent.py --agent-var root_agent --directory ./wrapped-agent

agentkit init wrapped-server --from-agent ./agent.py --template agent_server --directory ./wrapped-server
```

Enter the directory specified by `--directory`, then configure the cloud platform, model, and credentials using the [Quickstart](/productions/agentkit-cli/preview/en/quickstart) before deploying. For the `wrapped-agent` example:

```bash lines
cd wrapped-agent
agentkit launch
```
