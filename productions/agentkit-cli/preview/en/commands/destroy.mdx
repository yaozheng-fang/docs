`destroy` removes the current deployment described by the root lifecycle configuration, `agentkit.yaml`. In `local` mode it stops and removes the local container. In `cloud` and `hybrid` modes it deletes the recorded AgentKit Runtime and clears the corresponding deployment state.

## destroy

<Warning>
This command deletes the container or cloud Runtime selected by the lifecycle configuration. Confirm that `--config-file` points to the intended project before proceeding; non-interactive execution requires `--force`.
</Warning>

| Flag / Argument | Description | Default |
| --- | --- | --- |
| `--config-file <path>` | Lifecycle configuration path. | `agentkit.yaml` |
| `--force` | Skip the confirmation prompt and delete immediately. | `false` |

```bash lines
agentkit destroy --config-file ./agentkit.yaml
```

In automation, add `--force` only after checking the target configuration. After completion, inspect the deployment record with `agentkit status --config-file ./agentkit.yaml`; for cloud targets, also check `agentkit runtime list`

This command destroys a runtime rather than cleaning up every project resource. Check and manage registries, build artifacts, knowledge bases, memory collections, and release-created messaging proxies separately
