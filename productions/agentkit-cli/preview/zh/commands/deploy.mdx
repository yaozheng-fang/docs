`deploy` 根据当前项目的生命周期配置部署运行时。该命令不会先构建镜像；需要一次性完成构建与部署时，使用 [`launch`](/productions/agentkit-cli/preview/zh/commands/launch)。需要使用 `.agentkit/agentkit.yaml` 的云端发布配置、消息渠道或前端发布流程时，使用 [`release`](/productions/agentkit-cli/preview/zh/commands/release)。

在项目目录先完成 `agentkit build`，确保同一份生命周期配置已记录构建结果。云端和混合模式需要目标平台与区域的运行时管理权限，本地模式需要 Docker

<Warning>
部署会创建或更新配置所指向的运行时，可能替换正在提供服务的应用并产生云资源费用。执行前核对云厂商、区域与运行时名称
</Warning>

## deploy

读取 `agentkit.yaml`，按 `common.launch_type` 选择本地、云端或混合部署策略，并把部署产生的运行时 ID、端点或本地容器状态写回配置文件。

| 标志/参数 | 说明 | 默认值 |
| --- | --- | --- |
| `--config-file <path>` | 生命周期配置文件路径。 | `agentkit.yaml` |
| `--harness <name>` | 从当前目录的 `<name>.harness.json` 部署 Harness 运行时，而不是读取 `agentkit.yaml`。 | — |
| `--region <region>` | Harness 部署使用的 AgentKit 区域。 | Harness 配置或当前云环境 |
| `--volcengine-access-key <key>` | Harness 部署使用的 Volcengine Access Key。 | 环境变量或全局配置 |
| `--volcengine-secret-key <key>` | Harness 部署使用的 Volcengine Secret Key。 | 环境变量或全局配置 |
| `--discovery-url <url>` | Harness 部署使用的 OIDC discovery URL；传入后启用 OAuth2/JWT 鉴权。 | — |
| `--allowed-id <ids>` | Harness OAuth2/JWT 允许的客户端 ID，多个值用逗号分隔。 | — |
| `-y, --yes` | Harness 同名运行时已存在时跳过确认并更新。 | `false` |

```bash lines
agentkit deploy --config-file agentkit.yaml
```

<Note>
`deploy` 会在部署前执行必要的服务预检。预检失败时，交互终端会提示是否继续；需要在自动化环境中控制预检行为时，使用 `launch --preflight-mode` 完成构建与部署。
</Note>

## Harness 部署

传入 `--harness <name>` 时，CLI 会读取当前目录下的 `<name>.harness.json`，转换为运行时环境变量，临时生成生命周期配置，再执行云端构建与部署。若传入 `--discovery-url`，必须同时通过 `--allowed-id` 提供至少一个允许的客户端 ID。

<Warning>
Harness 部署会创建或更新云端运行时，并可能改写当前目录的 `harness.json` 以记录端点、运行时 ID 与鉴权信息。执行前确认当前目录、Harness 名称和目标项目。
</Warning>

```bash lines
agentkit deploy \
  --harness support-bot \
  --region cn-beijing \
  --discovery-url https://identity.example.com/.well-known/openid-configuration \
  --allowed-id web-client-id \
  --yes
```



## 运行时角色

创建运行时时，显式指定的 IAM 角色必须存在；未指定角色时，CLI 优先复用具备 `AgentKitDefaultRuntimeAccess` 策略的角色，否则创建新角色。更新运行时会保留原角色，不自动修改已有角色策略；启用定时任务时所需的 TOS 前缀权限另行配置

部署后使用 `agentkit status` 检查状态，并用 `agentkit invoke run "hello"` 验证应用响应。前者确认运行时状态，后者还会调用应用与模型；模型鉴权失败应检查运行时环境变量，而不是重新执行构建
